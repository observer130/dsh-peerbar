## 2. P0：先修（体验断点）

### T1 远端会话历史截断，且无法上翻

**现象**：打开远端会话只看到最近一小段消息；往上滚不会加载更早的，也没有「加载更多」入口。长会话直接「丢头」。

**证据链**（三处叠加，缺一不可）：

| 位置 | 问题 |
| --- | --- |
| `lib/remote.js:229-233` | `clampLimit` 上限写死 **50**，客户端传 `limit=200` 被压到 50 |
| `lib/remote.js:247` | `session/page` 请求里**没有 `beforeSeq`**，只能取「截至 throughSeq 的最新一页」 |
| `lib/index.js:144-145,161` | 路由解析了 `before` 参数却没传给 `readRawPage`（死参数） |
| `lib/client.js:336,455` | 事件窗与会话快照的 `hasMore` **恒为 false**，官方「上翻加载」触发器不启动 |
| `lib/client.js:567-568` | `loadOlder` / `loadThrough` 是空实现（`async () => {}`） |

**做法**：
1. 宿主半：`readRawPage(host, sessionId, limit, { beforeSeq })` 把 `beforeSeq` 透传到 `session/page`；`/session` 路由把 `before` 传下去。
2. `clampLimit` 上限提到 200（单页仍建议 50，翻页时 50/页）。
3. 客户端 binding 维护 `firstSeq`，实现 `loadOlder()`：拉 `before=<firstSeq>&limit=50` → `change: { kind: 'prepend', entries, hasMore }`（官方 assembler 支持 `prepend`，见 `dsh-client-ui-conversation` 的 `assembler.prepend(entries, hasMore)`）。
4. 快照的 `hasMore` 用首页响应的真实值初始化，`loadingOlder` 在请求期间置 true（防重复触发）。

**验收**：
- 单测：`readRawPage` 带 `beforeSeq` 时参数正确；路由透传 `before`。
- 真机：挑一条 >50 事件的历史会话，上滚能连续翻到 seq=1，滚动位置不跳（官方 prepend 负责锚定）。

### T2 远端消息里的图片/附件

**现象**：远端会话里带图片的消息显示不出来；在远端会话里粘贴图片/添加附件发送也不通。

**证据**（代码路径判断，尚未真机验证——远端会话里没有图片消息时无感）：
- 图片渲染走官方 `loadImage: (attachment) => ctx.uiConversation.imageUrl(sessionId, attachment)`（`dsh-client-ui-conversation/lib/client.js:17220`），而 `imageUrl` 是**按本地 session 授权**从本地附件库解析的（同文件 `4107` 起）→ 远端 attachment 引用在本地附件库里不存在，解析必失败。
- `lib/client.js:563` `readAttachment` 直接返回 `peerbar/unsupported`。
- 白名单里没有任何上传/附件端点（`lib/rpc.js`）。

**做法（两条路，先做渲染再做发送）**：
1. **渲染**：宿主半加只读代理 `GET /hosts/<id>/session/<sid>/attachment/<ref>`，用 host cookie 转发远端附件读取；客户端把 `ctx.uiConversation.imageUrl` 对远端 sessionId 的调用重定向到该代理（或在 binding 上提供 `loadImage` 覆盖）。
2. **发送**：远端上传端点确认后加进白名单（需要先调研 `session/prompt` 的 `content` 是否接受 base64 内联；若接受则免上传）。
3. 都不通时，composer 对远端会话**显式禁用附件按钮并提示**（不要静默失败）。

**验收**：远端历史里带图的消息能显示；在远端会话发一张图，远端会话记录里出现该图片事件。

## 3. P1：能力补齐

### T4 远端会话斜杠命令

`lib/client.js:569` `command: async () => readOnlyFail()`。官方命令面板（`/`）在远端会话里点了就报「远端暂不支持此操作」。

**先调研**：命令到底走哪个端点（本地是 `session.command` 还是 controller 本地方法），确认远端是否有对应 RPC；有则进白名单并实现，无则把 `/` 面板在远端会话里禁用（不要报错）。

### T5 远端新增工作区

`workspace/create` 已在白名单（`lib/rpc.js:20`）但没有任何调用方——即「只能管已有工作区，不能注册新目录」。

**做法**：远端工作区列表底部加「添加远端工作区」，输入远端绝对路径 → `workspace/create {path}` → 刷新（幂等，已注册则直接返回 `created:false`）。
远端目录选择器不可用（`directoryPicker` 明确不放行），所以只能手输路径 + 路径存在性校验。

### T6 侧栏拖拽排序

接管 `sidebar.workspaces` 后，官方树的拖拽排序能力丢失（本机也没了：`lib/client.js` 里没有任何 `draggable`/`dragstart`）。

- 远端：`workspace/insertSessionBefore {workspaceId, sessionId, beforeSessionId}` 已在白名单（`lib/rpc.js:28`），未接 UI。
- 本机：需要调研官方本地排序通道（ui-workspace 内部 store / controller 方法），可能要 patch 到 `ctx.uiWorkspace`。

**范围建议**：先做同组内会话排序（本机+远端），工作区级排序单独一卡。

### T7 远端会话里的文件引用点击

远端消息中点击文件路径会走本地 `openFile`，可能打开**本机同名的另一个文件**（比打不开更危险）。

**做法**：远端会话下拦截 `openFile`，显示「这是远端文件（<host> 上的 <path>）」提示，不做本地打开；后续如要支持，需远端文件读取端点（当前白名单没有）。

## 4. P2：健壮性与细节

### T8 cookie 过期时写操作失败不重试

`lib/client.js:464-476` 的 `rpc()` 把 401 当成普通错误返回；用户点「发送/归档」瞬间会看到失败，虽然 5s 探活（`lib/index.js:25`）随后会换到新 cookie 自愈。

**做法**：捕获 `AUTH_REQUIRED` → 触发一次探活（`/hosts/<id>/probe` 或等 `state.refresh()`）→ 重试一次 → 仍失败才提示。

### T9 baseline 退化无提示

`readWorkspaceBaseline` 失败时探活仍算成功，只是没有 workspaceId；`groupSessions` 退回 cwd 合成，客户端对无 workspaceId 的组**不渲染 ⋯ 和 +**（上轮修复）——结果是「菜单凭空消失」且无解释。

**做法**：`/state` 带 `registryError` 字段；侧栏在该 host 的组头上给一个小提示（图标 + tooltip「工作区信息读取失败，仅只读」）+ 退避重试。

### T10 远端会话标题不实时同步

`createRemoteBinding` 的 `summary` 只在 `openRemote` 时构造一次（`lib/client.js:1440-1450`），合并快照直接用它注入（`876`）；轮询与 `state` 刷新都不会回写 `summary`，`session.rename` 也不改它。
→ 侧栏行会跟新（走 `/state`），但走 `binding.summary` 的那部分（主视图标题 / 窗口标题）会停在打开时的旧名，需重开会话。

**做法**：`usePeerState` 拉到新 state 后，把对应 binding 的 `summary.title/displayTitle` 更新并 `publishSession()`。
动手前先花 5 分钟实测影响面：改一个远端测试会话的名字，看主视图标题栏与浏览器标签是否变化。

### T11 折叠偏好 key 变更

远端组 fold key 从 `path` 改为 `workspaceId`（上轮修复的副作用），本地折叠偏好一次性重置。**只记录不做**；若要做，迁移一次旧 key 即可。

### T12 未读标记（可选）

非当前会话收到新回复时，侧栏只有 running 点，没有未读标记。官方 `inbox` 投影里可能有 `next-turn` 之外的状态，需先确认语义；确认后再决定是否做「未读圆点」。

## 9. 2026-10-26 追加：远端工作区右侧面板（验收反馈 #3）

> 现象：远端工作区打开后，右侧「工作区文件 / 新建终端 / 浏览器」三个面板无效。

**为什么无效（架构事实）**：这三个面板都是**本机服务**的视图，不是会话正文的一部分：

| 面板 | 数据源 | 远端为何失效 |
| --- | --- | --- |
| 工作区文件 | `ctx.remote.workspaceFiles.list(sessionId, path)`（`dsh-client-ui-sidebar-files`） | `ctx.remote` 绑定本机 host，用远端 sessionId 查本机文件库 → 查不到 |
| 新建终端 | `terminal/create` + `terminal/attach`（`dsh-client-ui-sidebar-terminal`） | 在本机起 shell、cwd 用远端路径 → 路径不存在/起错机器 |
| 浏览器 | 本机预览服务 | 预览的是本机端口；远端服务需要端口转发 |

也就是说，这不是「修个 bug」，而是**要给每个远端会话造一套远端 fs / 终端 / 预览的绑定**。

### T17 远端文件面板（只读，第一批）

- 远端端点已确认：`workspaceFiles/list|read|stat`，参数 `{workspaceFileScope, path}`（scope 传 sessionId 字符串），`readBytes` 也有。
- 做法：按 `sessionId → host` 归属，包一层 `ctx.remote.workspaceFiles.{list,read,stat}`，命中远端会话时转发到 `/hosts/<id>/rpc`；`changes`（实时变更流）是流式端点，第一版先退化为打开时刷新一次。
- 验收：远端工作区点「工作区文件」能列出远端目录、点开文本文件能预览。
- 规模：M。

### T18 远端终端（第二批，最大）

- 端点：`terminal/list|create|rename|close|retain|environment|shells|attach`；`attach` 是**流式**（PTY 数据双向），只能走 WS mux，且要处理 stdin/resize 帧。
- 做法：宿主半开 WS 代理通道，客户端把面板的 terminal 绑定按当前会话 host 路由；xterm 组件原样复用。
- 风险：安全面（等于把远端 shell 暴露给本机 UI，但本来就是同权用户）、断线重连、窗口 resize。
- 规模：L。

### T19 远端「浏览器」面板

- 先确认语义：官方这个面板是**本机 dev server 预览**。远端工作区要么（a）打开远端已监听端口的 URL（需要知道端口，且本机要能直连），要么（b）不做，改成「复制远端地址」。
- 建议先做（b）的降级提示，别硬做端口映射。
- 规模：S（降级）/ L（真转发）。

### 建议

先 T17（只读文件，收益/风险比最好），再评估 T18 是否值得（终端是重型功能，且远端 shell 与 SSH 重叠）。

## 10. 2026-10-26 已修：顶替 `sidebar.workspaces` 漏声明子座位

**症状**：启用插件后，新会话页点工作区下拉，「添加工作区…」整项消失（有插件才有）。

**根因**：`sidebar.workspaces` 是带子座位的 single 槽。官方 `ui-workspace` 的
register 里声明了 5 个子座位（`directoryFlow`、`session.menu.item`、
`session.row.action`、`sidebar.session.row.leading`、`.hover`）。我们顶替时只注册了
组件、没写 `children`，于是：

1. `sidebar.workspaces.directoryFlow` 不存在；
2. 目录选择器插件 `directory-picker-browse` 的注入生成器里，先注册 hero flow、
   再注入 sidebar flow —— 后者失败导致整个生成器中止；
3. 结果 `conversation.hero.workspace.directoryFlow` 没有任何 entry，
   `flowSource` 的 `getEntries().length > 0` 为假 → `addEntries = []` → 整项消失。

**修复**：按官方原样在 register 里声明这 5 个子座位（我们的组件不渲染它们，
但声明必须留着，否则别的插件的注入会断）。

**教训**：顶替 single 槽时，`children` 是**对别的插件的契约**，不是自己的可选项。
