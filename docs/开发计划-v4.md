## 1. 一句话

远端行不再是一等公民里的二等残废：菜单齐全、能发消息、能换模型，操作路径与本机**完全一致**（同一个原生 composer、同一套行菜单），只是数据面走 `session/*` / `workspace/*` RPC 代理。

## 2. 事实基线（写代码前，全部从安装版 `typert.host.js` 提取核实）

### 2.2 两个关键结构性事实

1. **`session/list` 不带 `workspaceId` / `archived` / `pinned`**（v3 因此把远端工作区标成只读）。
   但 `workspace/follow` 的 baseline 一次给全：`workspaceId`、`path`、`title`、`sessionIds`（手工序）、
   `archivedSessionIds`、`pinnedSessionIds`。workspaceId 的死结有两条解法：
   - **S1**：`workspace/follow`（若 HTTP RPC 信封能取到 baseline 帧）→ 数据最全，一次顶三；
   - **S2**：`workspace/create {path}` 幂等解析（会话 cwd → workspaceId），逐个反查。
   实验顺序 S1 → S2，S2 是保底（注意 `created:true` 说明把目录注册成了工作区，有轻微副作用）。
   **【P0 实验结论 2026-10-23，真机 nv50 验证】**：
   - `workspace/follow` 走 HTTP RPC 信封**被拒**（`gateway/signature-invalid: stream Remote methods
     must be opened through the stream carrier`）——流式端点只能走 WS。
   - **S1'（采用）**：WS mux 通道 `wss://<origin>/api/remote.mux`，帧协议
     `{type:'open',streamId,endpoint,payload:{args}}` → 下行 `{type:'item',streamId,value}` /
     `{type:'end'|'error',streamId}`；客户端可发 `{type:'cancel'|'end'|'item',streamId}`。
     用 dsh 自带 `ws` 包（`createRequire` 到 dsh node_modules，`rejectUnauthorized:false` + cookie 头）
     连上即取到 baseline 帧（2394B）：`{type:'baseline',value:{items[],archivedSessionIds[],pinnedSessionIds[]}}`。
     Node 22 内置 WebSocket 不行（不能带 cookie 头/放行自签）。
   - **S2（备选，已验证无副作用）**：`workspace/create {path: cwd}` → `{workspace:{workspaceId,path,title,
     sessionIds…}, created:false}` 幂等解析；对 nv50 四个 cwd 全部 `created:false`，
     sessionIds 与 session/list 按 cwd 分组完全一致（14/14、2/2、3/3、2/2）。
   - 附带发现：`session/list` **不过滤归档**（host 侧 list.js 只按 updatedAt 排序），archived/pinned
     只在 workspace registry——所以侧栏归档过滤必须依赖 S1' 的 baseline。
2. **模型切换的调用面**：官方 model-selection 插件对会话发 `sessions.selectModel({sessionId,…})`
   （走 `ctx.remote.session.selectModel`），目录走全局 `ctx.remote.session.modelCatalog()`（**无 sessionId 参数**）；
   当前模型读 `binding.session.projections.faceOf('modelSelection')`。
   → 三个点都要在 client 半按「会话归属 host」路由：`selectModel` 按 sessionId 路由，
   `modelCatalog` 按当前主视图会话路由，`faceOf('modelSelection')` 用 projections 里的现成值。

### 2.3 增量刷新（续聊的实时性）

- `session/page` 返回的 records 带 seq；原生 `SessionEventWindow.change.kind='append'` 支持增量入窗
  （`assembly.ts` 的 `accept()`：revision+1 且 kind=append 时逐条 `assembler.append`）。
- 远端会话打开时挂轮询（2s，运行中 1s；后台标签降频），`session/page` 拉 `beforeSeq > 已见尾 seq` 的新段，
  diff 出新 records → 以 append 推入 window。
- prompt 成功后的本地 echo 由 `beginSubmission` 记入 `pendingSubmissions`（对齐官方 client.js 的 placement 语义），
  轮询到对应真实事件后 retire。

## 3. 方案要点

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 写通道 | 宿主半 **白名单 RPC 代理** `POST /hosts/<id>/rpc`，body `{endpoint, args}` | 逐端点铺路由会爆炸；白名单 + 已有 guard（同源+回环）守住安全面 |
| 状态源 | `workspace/follow`（或 S2 反查）补齐 workspaceId/archived/pinned | 对齐本机 `useWorkspaces` 数据形状，菜单态/分组/归档过滤全通 |
| 续聊 | 合成 SessionFace 的 `prompt/cancel/updateQueue` 接 RPC；composer 不用动 | 原生 InputBar 本来就是调 `session.prompt`，把只读 stub 换成真调用即通 |
| 模型 | patch `ctx.remote.session.selectModel/modelCatalog` 按归属路由 | 不自绘模型 UI，官方 seat 原样用 |
| 实时 | 轮询增量 append（不引入 SSE/WS） | 与现有 callRemote（一次性 request/response）同构，退避简单 |

**明确不做（本期）**：附件/图片上传（`receiptId` 链路复杂）、会话排序拖拽、终端、subagent 面板、SSE 流式。

## 修订（2026-10-26）：远程分组改为注册表驱动

验收 bug：没有会话的工作区 ⋯ 菜单报「工作区信息未就绪」。

根因是 v4 P1 的分组语义偷懒：`groupSessions` 完全由 `session/list` 的 cwd
合成工作区，于是

- 未归属任何注册工作区的会话（nv50 `/home/nwj` 的 4 条）被造成伪工作区，
  workspaceId 为空 → 工作区菜单无从下手，只能弹「信息未就绪」；
- 注册了但还没有会话的工作区根本不进树（groupSessions 见不到它）。

修正为与官方一致：

1. registry 有工作区时，**注册工作区全部出组**（0 会话也出，客户端显示
   「暂无会话」），组名用 registry `title`（改名即时生效）；
2. 会话按 accounted 关系归组；未 accounted 的进「未分组」桶
   （`ungrouped: true`、workspaceId 为 null，客户端按 `tree.ungrouped` 渲染）；
3. 未分组桶无可见行时整组不渲染；未分组/无 workspaceId 的组不渲染 ⋯ 菜单与
   「+」按钮（杜绝「信息未就绪」这条死路）；
4. registry 缺失（baseline 读取失败）时才退回 cwd 合成（保留 v3 退化行为）。

注意：远端组的 fold 状态 key 从 path 改为 workspaceId（本地折叠偏好一次性重置）。
