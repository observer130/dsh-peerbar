## 1. 一句话

> 在本机 dsh 的原生侧栏里，把多台远端 dsh 的工作区与会话**平铺成同一棵树**，用 Host 标签区分来源；传输走 HTTP/WS 直连，不用 SSH 隧道。

---

## 2. 背景与问题

现状（三台机器）：

| 机器 | dsh web 监听 | 备注 |
| --- | --- | --- |
| 本机（Arch） | `127.0.0.1:3080` | 由 `~/dsh-web.sh` 用 systemd-run 拉起，token 每次重启都变 |
| nv50 | `https://192.168.3.50:3080` | 自签证书，`--host 192.168.3.50` |
| m50 | `192.168.112.235` | 独立开发机 |

痛点：

- 每台机器一个网页标签，切换成本高、容易记错在哪台执行；
- 想在 A 机续聊 B 机开过的会话，只能去 B 机的页面里翻；
- 已有方案要么形态不对，要么太重（见 §3）。

## 3. 与既有方案的关系（为什么还要自研）

| 方案 | 形态 | 传输 | 为什么不用 |
| --- | --- | --- | --- |
| `dsh-fleet` | 右侧 dock + iframe，点卡片整页切换 | HTTP + 令牌（免隧道） | 不是「侧栏混排」，且 iframe 内是另一套 UI，等于换了个地方开标签页 |
| `Codingns4DSH` PeerHost | 原生侧栏聚合，功能齐 | HTTP + WS 受控代理（免隧道） | 一整套 43MB / 20 依赖（node-pty、werift、codemirror、xterm）、GPL-3.0；PeerHost 只是其中一个默认关闭模块，改不动 |
| `dsh-remote` | 原生「添加工作区」里的远程 tab | SSH/SFTP | 要走 sshd + SFTP + 远端镜像目录，正是想避开的隧道路线 |
| `dsh-sev` | 侧栏会话混排 | SSH 隧道 | 按 0.1.x 写，0.2.x 上核心功能失效 |
| dsh 内核 | — | — | 0.2.1-rc.2 **没有**内置远程 Host / 远程工作区概念（`dsh-workspace` 只登记本地目录；无 `client-ui-remote-*` 包），必须由插件补 |

**本项目定位**：只做「聚合视图 + 直连代理」这一层，不捆绑 IDE 套件，不复制远端工作区到本地，不接管远端的插件/UI。

## 4. 术语

| 术语 | 含义 |
| --- | --- |
| **Host** | 一个运行中的 dsh 实例，用 origin（`http(s)://host:port`）标识 |
| **本机 Host** | 当前浏览器连的那台，即插件宿主，`targetHostId = null` |
| **Peer Host** | 在本机登记、被聚合的远端 dsh，必须有 `hostId` |
| **虚拟 ID** | 跨 Host 的唯一资源标识，格式 `peerbar:<hostId>:<kind>:<rawId>`，前端只见虚拟 ID |
| **源标签** | 侧栏工作区名旁的 Host 徽标（颜色 + 短名） |
| **快照** | 某 Host 当前的工作区/会话列表 + 探活状态，带 `fetchedAt` |

## 5. 目标与非目标

### 5.1 目标（v0.1 必须达成）

1. 一次登记多台 Peer Host，侧栏里能一眼看出哪个工作区在哪台机器；
2. 点开远端工作区能看到它的会话列表（标题、最后活动、运行状态）；
3. 远端断线时**不崩溃、不串数据**：工作区置灰、可展开缓存、自动重连；
4. 全程不依赖 SSH、不在远端开额外端口、不需要把远端 `dsh web` 暴露到公网；
5. 只读聚合：不修改远端任何数据（v0.1 明确不做写操作）。

### 5.2 非目标（v0.1 明确不做）

- ❌ 跨 Host 复制/迁移会话、同步文件、合并历史；
- ❌ 远端文件树、Git 面板、终端、审批回传（这些是 Codingns4DSH 的活）；
- ❌ 把远端插件 Bundle / UI Slot 加载到本机（远端只提供数据，不提供 UI）；
- ❌ 通用反向代理（禁止任意 URL / 任意 WS 帧转发）；
- ❌ 中转/公网穿透（只支持局域网或可直连的地址）；
- ❌ 移动端专门适配。

## 6. 用户场景（v0.1 验收都基于这三条）

**S1 一眼看清**：打开本机 dsh，侧栏自上而下是「本机工作区」+「nv50 的工作区（绿色标签）」+「m50 的工作区（蓝色标签）」。

**S2 跨机找会话**：在侧栏搜索框里搜关键词，能命中远端会话标题；点进去会话内容可读（v0.1 至少只读正文，见 §7 P1）。

**S3 断线容错**：拔掉 nv50 网线 → 侧栏该组置灰、仍能展开缓存列表、5 秒后自动重试；恢复后自动回到彩色并刷新。

## 7. 功能需求

### P0（MVP，必须先跑通）

**P0-1 Host 注册与探活**

- 设置页（`settings.section`，id `peers`）可增删 Peer Host：名称、origin、访问令牌；
- 保存后立刻探活：`GET <origin>/`（或健康端点）判定 ① 可达 ② 是 dsh ③ 版本/契约是否匹配；
- 探活结果落盘并推给前端：`online | auth-required | unreachable | not-dsh | incompatible`；
- 验收：填错端口 → 显示 `unreachable`；填 nv50 但不给令牌 → `auth-required`；正确 → `online` 且显示 dsh 版本。

**P0-2 侧栏 Host 过滤条**

- 注入原生侧栏工作区树（slot `sidebar.workspaces`，见 §11），在树顶部加一条紧凑的 Host 过滤条：`全部 / 本机 / 各 Peer`；
- 点击切换过滤，不刷新页面；选择状态存 localStorage；
- 验收：三台机器时过滤条不超过 40px 高，窄屏（<900px）折叠成下拉。

**P0-3 远端工作区 / 会话平铺**

- 本机与各 Peer 的工作区合并成一个有序列表，顺序：本机在前（保留原生顺序），Peer 按用户配置顺序；
- 每个 Peer 工作区行带源标签（颜色 + 短名）；
- 展开工作区 → 显示该工作区的会话（标题 / 最后活动 / 运行中脉冲）；
- 会话行复用原生行渲染能力（`sidebar.workspaces.session.row.action` 可挂自定义行操作）；
- 验收：nv50 的 3 个工作区出现在本机侧栏，点展开能看到其会话，且会话 ID 与远端页面上一致。

**P0-4 断线与缓存**

- 缓存上一份成功的快照（不含会话正文），落盘到 `~/.dsh/dsh-peerbar-cache.json`；
- 断线时该 Host 组置灰，仍可展开缓存，行点击提示「断线中」；
- 每 5s 复检，连续失败指数退避到最多 60s；恢复后拉新快照并重新着色；
- 验收：S3 场景。

**P0-5 安全与边界**

- 令牌只存宿主侧（`~/.dsh/dsh-peerbar.json`，0600），响应里只回 `hasToken: true/false`，**永不回传明文**；
- 所有变更类接口（增删改 Host、刷新）只接受**同源 + 回环** POST；
- 代理只允许白名单内的远端路径前缀（§9），禁止任意转发；
- 验收：用 curl 从另一进程带 `Origin: http://evil` 调变更接口 → 403；响应 body 中 grep 不到令牌。

### P1（MVP 后第一批）

**P1-1 远端会话续聊【待验证：协议缺口】**

- 点开远端会话 → 中栏显示消息流、输入框可发消息，请求路由回该 Host；
- 依赖 dsh 0.2.x 的 Conversation Remote 协议；Codingns4DSH 的规格里记录过「原生 Session binding / Conversation Remote 协议缺口」，说明这里可能需要自己包一层。
- **先做 spike（§12-S3）再承诺**；若协议不通，降级为：v0.1 只读正文 + 「在远端打开」按钮。

**P1-2 Host 外观**：别名、标签颜色（按名字派生默认色）、排序拖拽。

**P1-3 组合搜索**：一次搜索命中多 Host 的会话标题，结果按 Host 分组。

### P2（远期，非本版本）

审批/提问回传、远端文件预览、远端 Git 状态、远端终端。

## 8. 技术方案

### 8.1 分层

```
浏览器（本机 dsh Web UI）
   │  只连本机，单 origin
   ▼
本机 dsh 宿主
   ├── 客户端半边：往 sidebar.workspaces 注入 Host 过滤条 / 源标签 / 远端行
   └── 宿主半边：/dsh-peerbar/api/*  ← 唯一的跨机出口
          │  Node 侧 HTTP + WS（受控白名单）
          ├── nv50: https://192.168.3.50:3080
          └── m50:  http://192.168.112.235:3080
```

关键决策：**跨机请求全部由宿主半边发起**，浏览器不直连远端。原因：远端 dsh 的 `/api` 要求按 authority 绑定的登录 cookie，浏览器跨 origin 拿不到；放宿主侧才能集中管理 cookie/令牌、做白名单与缓存。

### 8.2 客户端半边

- 入口形态：`inject = ["slots"]`，`ctx.slots.inject('sidebar.workspaces', ...)` + `ctx.slots.register({ name: 'sidebar.workspaces', id: 'peerbar', order })`；
- 过滤条 + 源标签走这个 slot；不要动 `shell.overlay`（那是浮层，会被当成独立窗口）；
- 会话行操作挂 `sidebar.workspaces.session.row.action`；右键菜单挂 `sidebar.workspaces.session.menu.item`；
- 数据来源：`GET /dsh-peerbar/api/state`（一次拿全量快照），Host 状态变化用轮询（5s）即可，v0.1 不上 SSE。

### 8.3 宿主半边

- 用 `ctx.inject(['webServer'], ...)` 等 webServer 就绪后再注册路由（否则全新启动时静默失效——这是 dsh-fleet 踩过的坑，见其 README「实现说明」）；
- 路由注册：`ctx.webServer.register({ kind: 'exact' | 'prefix', path, handler })`，返回 disposer；重复路径会抛错，所以路径全部带 `/dsh-peerbar/` 前缀；
- 需要 WebSocket 时用 `ctx.webServer.registerUpgrade({ path, handler })`（v0.1 暂不用）；
- 读自身监听信息：`ctx.webServer.port` / `.protocol` / `.getOrigin()`。

### 8.4 虚拟 ID 与作用域

- 规则：`peerbar:<hostId>:ws:<rawWorkspaceId>`、`peerbar:<hostId>:sess:<rawSessionId>`；
- `hostId` 用 origin 的稳定 hash（如 `sha1(origin).slice(0,8)`），避免用户改别名导致 ID 变化；
- **禁止**用裸 `workspaceId` / `sessionId` 做主键（不同 Host 会撞）；
- 前端所有回传宿主时都要带 `hostId`，宿主校验该 Host 是否仍登记、是否 online。

### 8.5 探活与快照

| 项 | 约定 |
| --- | --- |
| 探活 | 每 5s 一次 `HEAD/GET <origin>/`，10s 超时；连续失败 → 指数退避 5→10→20→40→60s |
| 快照 | 探活成功后拉工作区+会话摘要，写入内存 + 磁盘缓存 |
| 缓存失效 | 超过 24h 丢弃；Host 被删除立即清 |
| 并发 | 各 Host 独立并发，单 Host 失败不影响其他 |

### 8.6 错误模型

统一响应 `{ ok: false, code, message, hostId? }`，`code` 取值：

`unreachable` / `tls-error` / `auth-required` / `not-dsh` / `incompatible` / `timeout` / `bad-request` / `denied`

前端按 `code` 决定文案与重试策略；`tls-error` 单独给「怎么装证书」的提示（见 §12-S2）。

## 9. 插件自有 API 契约（宿主半边）

全部挂在 `/dsh-peerbar/api/` 下。

| 路由 | 方法 | 说明 | 备注 |
| --- | --- | --- | --- |
| `/state` | GET | 全量快照（Host 列表 + 各自工作区/会话 + 状态） | 前端每 5s 轮询 |
| `/hosts` | POST | 新增 Host `{ name?, origin, token }` | 同源 + 回环 |
| `/hosts/:id` | PATCH | 改名 / 改色 / 改令牌 | 同上 |
| `/hosts/:id` | DELETE | 移除 Host | 同上 |
| `/hosts/:id/probe` | POST | 立即探活 + 重拉快照 | 同上 |
| `/sessions` | GET | 某 Host 的会话列表 `?hostId=&workspaceId=` | 命中缓存则不回源 |

**代理白名单**（只允许打这些远端路径，其余一律 403）：

- `GET /`（页面探测，用于判定是不是 dsh）
- `GET /api/session/list`、`GET /api/session/projections`（方法名见 §11 已核实项）【待验证：workspace 枚举方式】
- `GET /api/workspace/*`（若存在，按描述符确认后加入）

## 12. Spike 清单（写代码前必须清的 3 个雷）

| ID | 问题 | 为什么卡 | 验证方法 | 失败时的降级 |
| --- | --- | --- | --- | --- |
| S1 | 远端 `/api` 的**鉴权**：浏览器首次访问靠 `?token=` 换 authority 绑定的 cookie；宿主侧没有浏览器，怎么拿到可用凭据？ | 拿不到就什么都读不到 | 用 `curl -i https://192.168.3.50:3080/?token=<远端启动 token>` 看 303 与 `Set-Cookie`，再用该 cookie 打 `/api/session/list` | 让用户在设置页粘贴远端「会话令牌」，插件按令牌换取 cookie 并维护 jar；或远端开一个只读的 peerbar 端点 |
| S2 | **自签证书**：Node 侧 fetch/WS 到 nv50 会因证书不受信失败 | nv50 现在就是自签 https | 在宿主侧 `fetch('https://192.168.3.50:3080/')` 观察是否 `UNABLE_TO_VERIFY_LEAF_SIGNATURE` | ① 配置项支持 per-host `insecure: true`（仅局域网、需二次确认）；② 文档引导 `NODE_EXTRA_CA_CERTS`；③ 让 nv50 改 http |
| S3 | **远端会话正文/续聊**：0.2.x 的 Conversation Remote 是否允许跨 Host 直接消费？ | 决定 P1 做不做得动 | 探远端 `/api` 描述符，枚举 namespace/method，试着用 `session.projections` 拉一条会话的投影 | v0.1 只读：走会话日志文件（`~/.dsh/sessions/.../session.jsonl.zstd` 只能本地读 → 改为远端 peerbar 端点返回只读正文） |

另外两个**非阻塞**但要知道的点：

- 工作区枚举方法名尚未确认（`session.projections` 里可能带 `workspaceId` + `cwd`，够用就不另外找）；
- 远端若跑在 Desktop 壳里，`file://` + IPC 桥接的 fetch 路径与 Web 不同，需实测一遍。

## 13. 工程约定

```
dsh-peerbar/
├── package.json          # name: dsh-peerbar, dsh.bundle.patch, dsh.client.inject
├── cordis.patch.yml      # insert: - id: dsh-peerbar, name: dsh-peerbar
├── lib/
│   ├── index.js          # 宿主半边：路由、探活、缓存、代理
│   ├── hosts.js          # Host 注册表 + 配置读写
│   ├── probe.js          # 探活与错误分类
│   └── proxy.js          # 白名单代理 + cookie jar
├── client/
│   └── client.js         # 客户端半边：slot 注入
├── docs/                 # 本文件、开发记录、spike 结论
└── README.md
```

- **不引入构建步骤**：和 `dsh-fleet` 一样手写 ESM（`lib/*.js`），`dsh.client` 直接指 `client/client.js`，改客户端半边可热加载、改宿主半边必须重启 dsh；
- **零第三方依赖**（目标）：只用 `node:*`。若要 cookie jar，自己写 20 行而不是拉 `tough-cookie`；
- 日志一律走宿主 `ctx.logger`，前缀 `[peerbar]`，不要 `console.log`；
- 所有面向用户的文案走 i18n（`zh` / `en`），不要硬编码中文进渲染函数；
- 错误码集中在一个 `codes.js`，前后端共用；
