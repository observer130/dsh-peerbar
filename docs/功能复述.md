# 功能复述（以界面为准）

> 这份文档只讲「用户看到什么」，不讲架构。任何与它冲突的实现描述，以本文为准。
> 上一版翻车的原因：把「出现在原生侧栏列表里」实现成了「侧栏加一个图标，点开中栏整页」。

## 一句话

打开本机 dsh，**左边那一列本来就是工作区/会话列表**；本插件要做的，是让这一列在列出本机工作区之后，**接着列出 nv50、m50 的工作区，以及各自下面的会话**。点其中任意一条会话，右边正常的对话区就打开它。

不新开图标，不新开页面，不新开标签。

## 界面（文字线框）

```
┌─ 侧栏（官方那一列，原样） ────┬─ 中栏（官方对话区） ─────────┐
│ 工作区                        │                              │
│  ▾ dsh-peerbar          （本机）│                              │
│     · 重构 guard          ●    │   ← 点本机会话：官方行为不变   │
│     · S1 spike                 │                              │
│  ▸ notes                 （本机）│                              │
│  ▾ nv50                 [nv50] │                              │
│     · 修 usage 面板 401   ●    │   ← 点远端会话：这里读它的正文 │
│     · 部署 dsh-fleet           │                              │
│  ▾ m50                   [m50] │                              │
│     · 训练脚本调参             │                              │
│  ─────────────────────────    │                              │
│  ⚙ 设置                       │                              │
└───────────────────────────────┴──────────────────────────────┘
```

要点：

- **位置**：就是官方侧栏那棵树本身（`sidebar.workspaces` 占的那一块），不是它旁边的图标栏（`sidebar.panellist`），不是右侧栏，不是浮层。
- **连续性**：本机工作区在前（保持官方顺序），远端按用户排的顺序接在后面，视觉上是同一棵树，不要分「本地/远端」两个区块标题。
- **来源标签**：远端工作区名后面跟一个短标签（`nv50` / `m50`），颜色可配；本机不带标签（或者淡灰「本机」）。
- **会话行**：标题 + 最后活动时间 + 运行中指示（沿用官方行的视觉密度）。

## 交互

| 动作 | 期望 |
| --- | --- |
| 点远端会话 | 中栏显示该会话消息流（v0.1 只读；输入框禁用并提示「只读，请在远端继续」） |
| 点本机会话 | 完全走官方逻辑，插件不介入 |
| 点远端工作区名 | 折叠/展开该组，行为同本机组 |
| 远端断线 | 该组整体置灰；仍能展开看缓存标题；点行提示「nv50 连不上」，不白屏、不刷错误 |
| 远端恢复 | ≤10s 自动恢复彩色并刷新列表 |
| 关闭/卸载插件 | 侧栏回到纯官方形态，无残留 |

## 数据从哪来

- 远端：`POST <origin>/api/session/list`（RPC 信封，cookie 鉴权）。实测 nv50 返回 26 条，字段有 `sessionId` / `cwd` / `updatedAt` / `running` / `projections.values.title`。
- **远端不返回 workspaceId**，所以「远端工作区」是按 `cwd` 分组合成的：组名取 `basename(cwd)`，完整路径放 tooltip。
- 本机：沿用官方侧栏自己的数据源，不要另拉一份，否则会出现「同一会话两行」。

## 明确不做（上一版踩过的）

- ❌ 侧栏放一个图标、点开在中栏显示一整个聚合页（= 又开了一个页面）
- ❌ 设置页当主界面。Host 登记/探活/令牌是**底座**，不是功能
- ❌ iframe 嵌远端页面、右侧 dock、全屏浮层
- ❌ SSH 隧道、把远端目录镜像成本地目录
- ❌ 修改远端任何内容（v0.1 只读）

## 一条硬约束（决定实现路线）

`sidebar.workspaces` 在 slot 目录里是 **`single`**（`dsh-cordis-client-runner` 的 catalog 原文：`key: "sidebar.workspaces", kind: "single"`），由官方的 ui-workspace 独占。也就是说：**没有「往里追加几行」的接口**。想让远端工作区出现在这一列里，只有两条路：

- **A. 顶替这个座位**：注册自己的组件到 `sidebar.workspaces`，自己画一整棵树（本机 + 远端）。位置和视觉最对；代价是官方那棵树的交互（新建/改名/拖拽/归档/右键菜单/目录选择）要自己实现一遍，且官方升级时容易碎。
- **B. 在 preboot 期包装原生 list store**：让远端条目以「本地工作区/会话」的身份被官方 UI 渲染。真正的「官方 UI 原样渲染」；代价是侵入最深，且 Codingns4DSH 自己在这条路上仍保留 DOM 降级路径，说明远端会话绑定存在协议缺口。

可选席位里那些 `sidebar.session.row.action` / `.leading` / `.hover` 只能给**已存在的行**加装饰，不能新增行 —— 这条已核实，别再往那个方向设计。
