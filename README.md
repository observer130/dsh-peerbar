# dsh-peerbar

把多台 dsh 聚合成**一个前端**：本机 + 各远端的工作区/会话出现在同一个官方侧栏里，点哪条就在官方中栏跟哪台的后续交互，执行始终在远端。走 HTTP/TLS 直连，不需要 SSH 隧道。

## 能做什么

- **一棵树（官方树）**：本机与各远端的工作区/会话混排在**官方侧栏**里；菜单、拖拽、未读、搜索都是官方的
- **按主机分组**：侧栏顶层是「本机 / nv50 / m50」三个可折叠行（本机显示器、远端云图标），展开就是该主机的工作区（官方「按工作区树」，零自绘）；切到「按工作区」时分组自动退场、标题补回主机后缀
- **侧栏默认清爽**：主机行/工作区组默认收起（新组收一次，升级后首次加载把已有组也收一次）
- **设置页只有一列「远程主机」**：标题 + 添加按钮 + 每台主机一张卡（状态、凭据、刷新 / 令牌 / 删除）；「添加」弹窗填名称、地址、令牌
- **官方中栏**：打开远端会话就是官方对话区，正文、工具调用、交付物、模型选择、斜杠命令都原样可用
- **改动文件卡片**：轮次末尾的「已编辑 N 个文件」卡片和它的 review 页签在远端会话里也有——两条按会话寻址的
  `/api/changes.summary|diff` 由宿主半带 cookie 转发给该会话所属 Host（摘要只存在记录它的进程里，Host 重启后
  先前轮次没有卡片，与官方一致）
- **远端会话管理**：置顶/取消置顶、改名、分叉、归档/取消归档；工作区可改名、删除、新建会话（都改投所属 Host）
- **远端续聊**：打开远端会话就能在原生输入框里发消息、停止、切换模型；回复通过轮询增量追加，无需刷新
- **反馈跟着会话走**：每条回复下的 👍/👎 与反馈详情读写都在该会话所属 Host 上
- **长会话能看全**：首屏 200 条消息，向上滚动自动加载更早的历史（按 Turn 对齐）
- **计划审阅与预览**：远端 `exit_plan_mode` 的计划卡片能审批，右侧栏「计划」页签能打开全文（`session/follow` + `session/page`）
- **定时任务跟着远端走**：远端改期/删除/投递后，本机「自动化任务」页自动刷新（转发 `schedule/changed`）
- **远端加工作区**：侧栏标题栏「＋」或新会话页的「添加工作区」，都能先选主机（本机 / nv50 / m50）再浏览该主机目录；远端目录直接在该 Host 注册，不建本机会话
- **未读提示**：官方 `ui-session` 直接读会话行状态，远端会话跑完同样显示完成圆点；打开即清除
- **拖拽排序**：官方组内/工作区拖拽对同一 Host 生效；跨主机拖拽明确拒绝（没有统一顺序）
- **状态可见**：每台 Host 的在线/延迟/凭据状态在设置页一栏看清；工作区信息读取失败时保留缓存标题

## 安装

### 从仓库目录（开发用）

1. 打开 DSH Desktop → 侧栏 **插件** → 标题旁箭头 → **安装第三方插件**
2. 填本仓库的绝对路径（如 `/home/nwj/Projects/dsh-peerbar`）
3. 装完点 **立即启用**，重启 DSH Desktop 使插件生效（改了宿主半也要重启）

### 从 tgz（分发 / 离线）

```sh
npm pack                      # 产出 dsh-peerbar-<version>.tgz（含 lib/、README、LICENSE，不含 docs/）
tar -xzf dsh-peerbar-<version>.tgz
```

把解压出的 `package/` 放到目标 profile 的 `node_modules/dsh-peerbar`（替换原来的软链或目录），
重启 dsh 即可。已在隔离 profile 实测：`/health` 200、侧栏接管、RPC 代理与 `ui-check --quick` 全过。

> 桌面版插件页能否直接选 `.tgz` 尚未验证；目前稳妥做法仍是填仓库目录，或按上面手工放进 profile。

## 使用

1. **设置 → 远程工作区**，添加 Host：名称、地址（如 `https://10.0.0.10:3080`）、访问令牌
2. 令牌就是远端 dsh 启动时 URL 里 `?token=` 后面那串；只在换 cookie 时用一次，之后 30 天内不必再填，远端重启也不用
3. 远端用自签证书时勾上「跳过证书校验」（仅内网）
4. 保存后自动探活；点 Host 名字可改名换色，↑↓ 调顺序，取消「启用」可临时停掉

## 注意事项

- **会在远端执行写操作**：发消息、停止、改名、归档/置顶、分叉、新建/删除工作区。这些都是你本人在这台 dsh 上本来就能做的操作，权限等同于你贴的那枚令牌
- **不搬运文件内容**：远端会话里的文件引用只做提示，不会在本机打开同名文件；要看内容请用右侧「文件」面板（只读，直接读远端）
- **远端 localhost 链接**：从聊天区走「侧边栏打开」时会被拦下并复制地址，避免打开本机同名端口；本机浏览器仍打不开远端服务，需要端口转发（本项目不做）
- **凭据只留在本机**：令牌与换来的 cookie 存在 `~/.dsh/dsh-peerbar.json`（权限 0600），响应里不会回传明文
- **自签证书**：默认拒绝不受信任的证书。局域网自签需对该 Host 单独打开「跳过证书校验」，仅建议内网使用；更稳的做法是给系统加信任根，或用 `caFile` 指定 CA
- **需要能直连**：不做中转、不做 NAT 穿透，只支持同网段或可直达的地址
- **不需要额外端口**：远端只要跑着 dsh，不用开 SSH，也不用新开端口

## 已知限制

- **侧栏是官方 UI**：插件不接管渲染，只把远端数据投影进官方 store；因此视觉与交互天然跟官方一致
- **拖拽排序有边界**：会话只能在同组内拖，工作区只能在同一个 Host 内拖，跨 Host 会被拒绝（没有统一顺序）
- **计划审阅/预览/用户提问都已接通**：审批卡片、`session/control` 投影、计划全文预览都走各自的桥；计划全文走 `session/follow` 单向 WS 桥 + `session/page` 翻页
- **定时任务实时刷新**：远端 `schedule/changed` 会转发给本机事件总线，「自动化任务」页无需刷新；远端任务的**新建**只能由该主机的 agent 触发（远端没有 `schedule/create` 端点）
- **远端右侧面板：终端、文档预览、定时任务可用，浏览器仍是本机视图**：「文件」只读代理到远端；**终端**走本机插件的双向 WS 代理（浏览器 ↔ 本机 ↔ 远端 `/api/remote.mux`），右侧栏复用官方 xterm 面板，刷新后由 `terminal/retain` 恢复进程与屏幕。**浏览器**面板仍在本机渲染：远端会话里点浏览器入口会提示「面板在本机渲染」，不再打开空白页；聊天区里指向远端 `localhost` 的链接改为「复制地址 + 提示」。真要看远端页面需要端口转发（本项目不做）。远端文件的 Markdown/代码/文本/图片/PDF 可在预览面板直接打开；Office（Word/PPT）转换暂不支持
- **远端文件面板会自动刷新**：变更走「浏览器 SSE → 本机路由 → 远端 mux → `workspaceFiles/changes`」；远端 dsh 的 watch 不可用时仍可手动刷新
- **界面只能从本机访问**：`/dsh-peerbar/api/*` 只接受回环 + 同源请求；从别的机器用浏览器打开本机 dsh 时，设置分区会报 403
